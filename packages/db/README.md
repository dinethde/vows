# @vows/db

The schema, the migrations, and the one place a connection pool is created.
Only `packages/server` imports this, on behalf of `apps/api` and `apps/worker`. The web app never does — it
talks to the API over HTTP (chapter 14).

```
src/schema/     one file per table, re-exported from index.ts
src/seed/       the development seed: settings and sample words for the albums
migrations/     generated by drizzle-kit. Never edit a generated file.
```

Tables are in chapter 07 of `architecture.md`. Every table has `created_at` and
`updated_at` as `timestamptz`, and `id` as a prefixed text id made in the
application (`alb_`, `pho_`, `drv_`, `enq_`, `rdr_`, `aud_`; see `src/ids.ts`).
The 22 albums are created by migration `0001`, not by the seed. Photographs are
never seeded here; they go in through the upload pipeline.

**Changing the schema**

1. edit the file in `src/schema/`
2. `pnpm db:generate` — writes a new SQL file in `migrations/`
3. read the SQL. If it drops a column or a table, stop and open an ADR first.
4. `pnpm db:migrate` against **your own Neon branch**
5. commit the schema change and the generated SQL together, in one commit
